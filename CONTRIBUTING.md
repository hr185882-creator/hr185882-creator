# Contributing

Contributions are welcome when they improve factual accuracy, source quality, documentation, accessibility, security, testing, or analytical clarity.

## Useful contributions

- correction requests supported by records;
- primary or official sources that materially improve a claim;
- broken-link reports;
- accessibility findings;
- security reports submitted privately;
- reproducible bug reports;
- documentation improvements;
- test cases that expose unsupported assumptions or inconsistent labels.

## Evidence submissions

For factual corrections or additions, include:

1. The exact statement or record at issue.
2. The proposed correction or addition.
3. A direct source link or complete source citation.
4. Why the source is relevant and authoritative.
5. Any uncertainty, conflicting evidence, or identity-matching risk.

Repetition of a claim across multiple derivative sources does not count as independent corroboration.

## Pull requests

A pull request should:

- have a narrow, descriptive scope;
- explain what changed and why;
- preserve existing evidence labels and uncertainty distinctions;
- avoid introducing private, defamatory, or unnecessary personal information;
- include validation steps where code or behavior changes;
- update documentation when the public meaning changes.

## Conduct

Discussion should focus on evidence, methods, implementation, and decision value. Harassment, threats, doxxing, identity attacks, and unsupported accusations are not acceptable.

## Sensitive reports

Do not use public issues for credentials, private data, vulnerability details, survivor information, or identity disputes involving nonpublic persons. Use the private contact route described in `SECURITY.md` or `CORRECTIONS_AND_PRIVACY.md`.
