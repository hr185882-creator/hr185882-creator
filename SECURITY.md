# Security Policy

## Reporting a vulnerability

Do not publish exploitable security details, private records, credentials, access tokens, or personal data in a public issue.

Report security concerns privately to:

- kazmihasan624@gmail.com

Include:

- affected project and URL;
- a concise description of the issue;
- reproduction steps;
- potential impact;
- screenshots or logs with sensitive information redacted;
- suggested mitigation, when available.

## Scope

Relevant reports include:

- exposed credentials or private files;
- unauthorized data access;
- injection or cross-site scripting;
- unsafe document rendering;
- broken access controls;
- privacy leaks or unintended identification;
- dependency vulnerabilities with a credible exploitation path;
- insecure deployment or configuration behavior.

## Responsible disclosure

Please allow reasonable time for investigation and mitigation before public disclosure. Good-faith research intended to improve security and privacy is welcome. Destructive testing, data exfiltration, impersonation, denial-of-service activity, and access beyond what is necessary to demonstrate the issue are not authorized.

## Data minimization

Security reports should contain the minimum sensitive material required to explain the issue. Do not send unrelated personal records or large private datasets.
